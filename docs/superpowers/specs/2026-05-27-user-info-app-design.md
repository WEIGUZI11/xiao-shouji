# User 信息独立软件设计

## 目标

在小手机桌面中新增一个独立的“User 信息”软件。用户可以在里面填写自己的基础资料、偏好、关系设定和长期记忆，并选择是否把这些信息加入发送给 AI 的上下文。开启后，微信聊天等 AI 请求会自动读到这些资料，让 char 更清楚“用户是谁”。

## 范围

本次只做一个轻量、稳定的第一版：

- 新增桌面入口“User信息”。
- 新增独立页面，用表单编辑用户资料。
- 资料保存在现有 Zustand 持久化数据里。
- 新增一个“发送给 AI”开关。
- 微信聊天系统 prompt 会在开关开启时注入用户资料。
- 空字段不会发送给 AI。

暂不做云同步、分应用细粒度权限、资料历史版本、加密导出或多用户档案。

## 用户资料字段

第一版字段如下：

- 昵称：默认沿用现有 `userName`。
- 头像：沿用现有 `userAvatar`，不在第一版重复实现上传。
- 年龄或身份：自由文本。
- 所在地或生活环境：自由文本。
- 性格：自由文本。
- 喜好：自由文本。
- 雷点或禁区：自由文本。
- 与 char 的关系设定：自由文本。
- 长期记忆：多行文本，适合写希望 AI 长期记住的事实。
- 发送给 AI：布尔开关，默认开启。

## 架构

新增 `UserInfoScreen` 组件，放在 `src/apps/user-info/UserInfoScreen.tsx`。它只负责编辑和展示用户信息，不直接调用 AI。

`src/store.ts` 新增 `userProfile` 数据结构和 `setUserProfile` action。资料继续通过现有 `persist` 中间件保存在 `localStorage` 的 `char-phone-framework` 下，和其他手机数据一起备份。

新增一个纯函数 `buildUserProfilePrompt(userName, userProfile)`，把非空资料格式化成一段适合放入 system prompt 的中文上下文。微信聊天在构建 system prompt 前调用它，并把结果拼到角色信息之后、聊天预设之前。

## 数据流

1. 用户打开“User信息”软件。
2. 用户填写资料，字段即时保存到 store。
3. 用户发微信消息。
4. `ChatScreen` 从 store 读取 `userProfile` 和 `userName`。
5. 如果 `sendToAi` 开启，构建一段“用户信息”上下文。
6. 这段上下文随 system prompt 一起发送给 AI。
7. 日志页仍能看到最终发送给 AI 的 messages，方便排查。

## 错误处理

表单不需要远程请求，所以不会有网络失败状态。空字段会被忽略。所有字段都按纯文本处理，不解析模板语法。资料太长时，格式化函数会限制输出长度，避免 prompt 膨胀。

## 测试

新增或扩展测试覆盖：

- `buildUserProfilePrompt` 会忽略空字段。
- 关闭 `sendToAi` 时返回空字符串。
- 有资料时输出包含昵称、关系设定、长期记忆等关键信息。
- 微信 AI prompt 构建时可以接收用户资料上下文。

## 验收标准

- 桌面能看到并打开“User信息”软件。
- 修改资料后刷新页面仍保留。
- 关闭“发送给 AI”后，聊天请求不包含用户资料。
- 开启后，聊天请求日志里能看到用户资料上下文。
- `npm run lint` 通过。
