# char 主动随机作息消息设计

## 目标

让 `char主动` 在用户开启后具备低频自动发消息能力。系统优先读取角色人设里的作息、职业、校园、生活习惯和主动程度，在合适时间附近让角色像真实联系人一样偶尔发来微信消息，例如“我下课了，你现在怎么样？”。

第一版强调可控、低频和贴人设：主动消息应像角色自己的生活继续发生，而不是后台刷屏或凭空制造大事件。

## 范围

- 在 `char主动` 页面新增“随机主动”开关。
- 开关开启后，前端在页面运行期间定时检查是否有角色满足主动触发条件。
- 优先根据角色人设里的明确时间线索触发，例如下课、下班、午休、失眠、早起、晚归。
- 没有明确时间线索时，根据角色主动程度进行很低频的生活随机问候。
- 只写入微信私聊消息和 `lifeEvents`，不写群聊、不直接弹锁屏通知、不自动调用 AI 或生图。
- 每条主动消息必须带去重 sourceId，避免同一角色同一时间段重复发送。

## 不做

- 不做后台常驻服务；关闭网页或 App 后不保证继续触发。
- 不做真实推送通知；后续可复用现有 proactive reminder 后端。
- 不让 AI 实时自由生成主动消息；第一版使用规则模板，降低不可控风险。
- 不读取其他角色私密数据来触发当前角色。
- 不主动生图、打电话、发红包或转账。

## 主动程度判断

从角色卡文本中提取主动倾向，只使用 `name`、`description`、`personality`、`firstMessage`、`systemPrompt` 等已有字段。

主动倾向分三档：

- 高主动：包含“主动、黏人、报备、话多、外向、喜欢聊天、会关心、经常发消息”等线索。
- 普通：没有明显倾向，按低频默认规则。
- 低主动：包含“不主动、慢热、沉默、寡言、克制、忙、冷淡、社恐”等线索。

高主动角色一天最多 4 次，普通角色最多 2 次，低主动角色最多 1 次。所有角色仍需满足冷却和时间段去重。

## 作息触发

新增纯逻辑解析函数，从人设文本识别常见作息：

- 上课 / 下课：识别“3点下课、下午三点下课、15:00下课、放学”等。
- 上班 / 下班：识别“6点下班、晚上十点下班、夜班结束”等。
- 午休 / 吃饭：识别“中午、午饭、午休、12点”等。
- 早起 / 早安：识别“早起、晨跑、早上六点、早安”等。
- 深夜 / 失眠：识别“失眠、凌晨、深夜、睡不着”等。

命中作息后，只在目标时间附近窗口触发，例如前后 20 分钟。消息内容使用固定模板加角色名字和时间场景：

- 下课：`我下课了，刚摸到手机。你现在怎么样？`
- 下班：`我刚忙完，终于能看手机了。你今天还好吗？`
- 午饭：`我准备吃饭了，你吃了吗？`
- 早起：`早，我醒了。今天想先问问你。`
- 深夜：`我有点睡不着，突然想看看你在不在。`

## 随机生活触发

如果角色当天没有明确作息命中，可以低频触发生活问候。随机触发必须满足：

- 当前角色没有处在冷却中。
- 当天主动次数未达到上限。
- 距离上次该角色主动消息至少 60 到 180 分钟，低主动角色取更长冷却，高主动角色取较短冷却。
- 概率受主动程度影响，高主动高一些，普通较低，低主动很低。

随机生活消息仍保持轻量，不创造重大剧情：

- `刚刚突然想起你，就来问一句。`
- `你现在在忙吗？我这边刚空下来。`
- `今天过得怎么样？我想听你说两句。`

## 架构

- 新增主动程度和作息解析纯函数。
- 新增 `buildRandomProactiveMessageWrites`，输入角色、聊天记录、生活事件、当前时间和开关状态，输出待写入微信消息与 life event。
- 复用现有 `createId`、`addMessage`、`addLifeEvent` 和 sourceId 去重模式。

扩展 `src/apps/active-events/ActiveEventsScreen.tsx`：

- 新增“随机主动已开启/关闭”按钮。
- 保留现有“刷新主动事件”和“主动提醒”能力。
- 页面文案说明随机主动只在本地运行期间生效。

扩展 `src/store.ts`：

- 新增 `randomProactiveMessagesEnabled: boolean`。
- 新增 setter。
- 升级 persist version 并在 migrate 中补默认值。

扩展 `src/App.tsx`：

- 新增轻量 hook，每 1 到 5 分钟检查一次随机主动消息。
- hook 只在开关开启时运行。
- 写入后记录 app log，便于在“报错/日志”里排查。

## 数据流

1. 用户打开 `char主动`，开启“随机主动”。
2. App 顶层定时检查当前时间。
3. 纯逻辑读取角色人设、已有 life events、聊天会话和开关状态。
4. 如果命中作息或低频随机条件，生成一条微信私聊消息。
5. 写入对应角色微信会话。
6. 写入 `lifeEvents`，sourceId 包含角色、日期、触发类型和时间段。
7. 后续检查通过 sourceId 和冷却规则避免重复。

## 错误处理

- 没有角色时不触发。
- 找不到微信私聊目标时不写入。
- 人设解析不到明确作息时只走低频随机，不报错。
- 非法时间、NaN 或系统时间异常时跳过本轮检查。
- 写入失败不重试刷屏，只写 app log。

## 测试

新增或扩展测试：

- 明确“下午三点下课”的角色在 15:00 附近会生成下课消息。
- 同一角色同一日期同一时间段不会重复生成。
- 高主动角色每日上限高于低主动角色。
- 低主动角色在随机生活触发中概率或资格更低。
- 关闭开关时不生成任何主动消息。
- store 默认值和 setter 正常迁移。

验证命令：

- `npx tsx src/apps/active-events/activeEventsLogic.test.ts`
- `npx tsx src/apps/active-events/activeEventsStore.test.ts`
- `npm run lint`
- `npm run build`

## 风险

- 太频繁会像刷屏，所以默认必须克制。
- 人设文本格式很自由，第一版只识别常见中文/数字时间表达。
- 规则模板可能显得重复，后续可再接入预设或 AI 改写。
- 前端定时只在 App 打开时可靠，后续如需关页面也发，需要接后端常驻或原生推送。
