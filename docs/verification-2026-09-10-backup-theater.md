# 数据导入与小剧场修复验收

范围：本轮只修数据导入、字数发送、续写与完整转入聊天；不改主题、角色数据、安装包标识或存储域名。

## 已确认的问题

- 导入只更新 localStorage，运行中的 Zustand 状态未同步；后续保存可覆盖导入结果。
- 合并快照取得早于异步图片导入，期间的新数据可能不在快照内。
- 失败回滚会清空图库再重导，增加数据风险和空间需求。
- 旧备份直接和当前版本合并会丢失独立迁移机会；BOM、存储键包装及无效 state 校验不完整。
- 自定义字数只取第一串数字，输出预算封顶 5000 Token；转入聊天只取前 700 字符。
- 首次打开历史正文时仍使用默认主题、角色和长度设置。
- 无模型配置或生成失败会以固定本地示例替代正文。
- 接口截断提示混入正文；续写入口不明显，无法看出实际字数是否达到目标。

用户所遇到的具体“400 字”返回和失败备份尚未拿到，不能断言所有故障来自同一个原因。

## 修复决策与安全边界

结构决策：Local Fix，无架构重写。执行按行为分段：导入提交与兼容、接口完成状态、小剧场字数与续写。
授权：用户明确要求修复。基线：原有备份、剧场测试通过，但缺少本轮回归案例。
每阶段约 1–4 个源文件及对应测试；不升级依赖、不删用户文件、不修改无关脏工作区。
图库仅补入缺少的图片；失败不会调用清空图库。主数据严格写入，写失败不触发有损压缩重试。
在图片异步处理结束后读取最新主数据并同步恢复运行态，重复导入保持去重。
按原规则保留当前同 ID 值和当前设置，只补入缺少的数据；不是覆盖恢复模式。
撤销本轮应仅撤回列出的局部修改，禁止 reset 整个工作区。

## 验证

- 导入：旧版迁移、运行态同步、紧接着后台保存、重复导入、空间不足、无效 state、BOM、存储键包装、双层 JSON 保留图片字段。
- 字数：模拟捕获实际请求，400 / 1200 / 4000 字分别发送 2024 / 4024 / 11024 max_tokens；提示词包含对应目标。
- 续写：连续两次 length 截断仍追加原文，不把系统上限提示存成故事；不足目标字数显示提醒。
- 完整性：4000 字正文转入聊天仍包含结尾，不再截取 700 字符。
- 界面组件隔离渲染：恢复历史的 4000 字设置、主题和世界输入，完整显示正文，上下两个继续写入口；旧版无效长度不导致页面崩溃。
- 类型检查和生产构建通过；全套 96 个测试文件通过后新增的界面回归测试也通过（合计 97 个）。构建仍有现有大分包体积警告。
- 实际本地页面可打开，自定义输入 4000 时界面显示目标 4000 字。未向玩家数据导入测试文件，未使用真实密钥发请求。
